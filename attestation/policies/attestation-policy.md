# Attestation Policy for qrap-demo

This document describes the attestation requirements for the qrap-demo repository.

## Overview

All release artifacts of qrap-demo must have cryptographic attestations to ensure:
- **Provenance**: Verifiable proof of where and how artifacts were built
- **Integrity**: Cryptographic assurance that artifacts haven't been tampered with
- **Transparency**: Public record of the software supply chain

## Required Attestations

### Production Releases

All artifacts released for production use MUST have:

1. **Provenance Attestation**
   - Must be generated by a trusted CI/CD system (GitHub Actions)
   - Must include source repository, commit SHA, and build timestamp
   - Must be signed with the repository's signing key

2. **SBOM (Software Bill of Materials)**
   - Must list all direct and transitive dependencies
   - Must include version and license information
   - Should use SPDX or CycloneDX format

### Development/Pre-release

Development builds SHOULD have:
- Provenance attestation (recommended)
- SBOM (optional)

## Artifact Types

The following artifact types are produced by qrap-demo:

| Artifact | Type | Required Attestations |
|----------|------|----------------------|
| Docker image | container-image | provenance, sbom |
| WASM module | wasm-module | provenance |
| Python wheel | python-wheel | provenance, sbom |
| Binary releases | binary | provenance |

## Signing

### Key Management

- Signing keys are NOT stored in this repository
- Keys are managed through:
  - Sigstore/Cosign keyless signing for public releases
  - GitHub OIDC for CI/CD attestations

### Verification

Attestations can be verified using:
- `cosign verify-attestation`
- `gh attestation verify` (GitHub CLI)
- Custom verification scripts in `attestation/scripts/`

- `required-attestations.dev.yaml` - Development requirements

## Exceptions

Exceptions to this policy require:
- Documented justification
- Security team approval
- Time-limited exception period
